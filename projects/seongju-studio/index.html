작동 원리와 작업 과정

팀과 역할을 구성브리프에서 제작 순서로작업을 나누고 실행실행 화면으로 검토하고 승인회의 내용을 작업으로 연결진행과 사용량을 확인

1. 팀과 역할을 구성

기획·아트·클라이언트·백엔드·QA로 팀을 나누고 팀장과 담당자를 정합니다. 사람 화면에서 사원증을 고르면 업무 지시, 메시지, 인사 기록을 열 수 있습니다.

Claude Code나 Codex 같은 실행기, 사용할 모델과 스킬·MCP, 파일·셸 권한, 작업별 시간·비용 한도를 직원마다 설정합니다. 수정 요청과 제 피드백은 다음 작업에 참고할 직원 기억으로 남길 수 있습니다.

2. 브리프에서 제작 순서로

새 작업은 게임·앱·영상·3D 에셋에 맞는 플레이북으로 시작합니다. 게임 MVP는 콘셉트, 기획서, 기술·아트 검토, 작업 분해, 병렬 제작, 기기별 QA와 최종 승인으로 이어집니다.

이미 진행 중인 프로젝트는 기존 Git 저장소를 가져옵니다. 기준 브랜치와 할 일을 입력하면 가져온 저장소를 기준으로 작업을 이어갈 수 있습니다.

3. 작업을 나누고 실행

작업 카드에 담당자와 결과 기준을 붙입니다. 코어는 큐와 Git 원본을 관리하고, 러너는 맡은 작업을 별도 Git worktree에서 실행합니다. 필요한 도구나 기기가 연결된 러너를 지정할 수 있습니다.

작업 상세에서 담당자, 실행 기록, 변경된 파일과 diff를 봅니다. 수정 요청이 오면 같은 작업 브랜치에서 이어가고, 대표 결재가 필요한 변경은 승인 뒤 main에 합칩니다.

4. 실행 화면으로 검토하고 승인

화면 작업은 변경 브랜치에서 웹 데스크톱·모바일 화면이나 Unity 게임 화면을 찍어 결과 보고에 붙일 수 있습니다. Unity는 컴파일, EditMode·PlayMode 테스트, 첫 씬 플레이 확인을 작업에 연결할 수 있습니다. Blender 모델링·FBX 작업도 러너에서 수행할 수 있습니다.

팀장은 코드 변경과 캡처를 보고 통과 또는 수정을 요청합니다. 기기별 QA에서 들어온 이슈는 QA 총괄이 모아 수정 작업과 재검수로 연결합니다. 저는 결재함에서 최종 승인하거나 사유를 남겨 돌려보냅니다.

5. 회의 내용을 작업으로 연결

회의실에서 안건과 참석자를 고릅니다. 직원들이 의견을 주고받으면 사회자가 결정 사항, 할 일, 남은 질문을 회의록으로 정리합니다. 담당자가 정해진 할 일은 그 자리에서 작업 카드로 만들 수 있습니다.

메신저에는 개인 지시, 작업 보고, 결재 결과가 이어집니다. 회의록을 지식 저장소에 남기면 같은 프로젝트의 이후 작업에서 참고할 수 있습니다.

6. 진행과 사용량을 확인

어떤 직원·모델·작업에 실행 시간과 토큰이 들어갔는지 집계합니다. API 사용 비용과 구독 내 사용량의 환산값을 나누어 보고, 수정 요청이나 병합 충돌로 다시 한 작업에 쓴 비용도 확인할 수 있습니다.

검토와 직원별 학습

웹 게임 검토에서는 정지 화면에 더해 실제로 입력을 보내 실행 오류와 긴 멈춤을 확인하도록 했습니다. 검토자는 보고서에서 같은 작업의 변경 코드와 실행 결과를 함께 볼 수 있습니다.

어느 커밋을 검토했는지 저장해 수정 요청 뒤에는 새 변경만 볼 수 있게 했습니다. 고쳐야 할 문제가 마지막 검토에도 남으면 자동 병합을 멈추고 운영자 결재로 넘깁니다. 직원별로 맡은 역할에 맞는 스킬과 MCP 도구를 제안할 수 있고, 설정된 정책에 따라 추가합니다. 채택이나 실제 사용을 경험치에 반영하고, 직원이 자신의 기억을 정리할 때는 운영자가 남긴 기억과 이전 상태를 보존합니다.
