실행 화면과 구조

시연 영상

재구축에서 맡은 범위

2026년 8월부터 새 저장소에서 Unity 앱을 설계·구현했습니다. 기존 Node.js 서버를 이어서 개발했고, 9월부터 React 웹을 만들었습니다. Electron 런처에는 상담실 입장 링크를 새 앱으로 넘기는 경로를 추가했습니다.

  • Unity. Photon Fusion 2로 상담 기록 상태를 공유해, 기록 중인 방에 늦게 들어온 사람도 동의 안내를 받도록 했습니다. 동의 전 음성은 기록에서 제외했습니다. 맵은 해당 공간을 열 때 CDN에서 받도록 바꿨습니다.
  • 서버와 관리자. 기존 앱과 웹의 API 계약을 유지하면서 개인정보 접속기록, 로그인 실패 잠금, 파기 도구를 구현하고 관리자 화면을 보강했습니다.
  • 새 웹과 런처. React로 상담실 예약과 입장 화면을 만들고 새 웹과 런처가 개발 환경에서 연결되는지 확인했습니다.

상담 기능 개발

  • 상담실 입장과 공간 이동. 예약 링크를 통해 런처에서 앱을 열고 상담실로 들어가는 흐름을 연결했습니다. 방마다 입장 권한을 확인하고, 지도에서 선택한 공간의 맵만 CDN에서 받도록 했습니다. 특별관의 입장 지점과 문, 의자·스크린 상호작용을 옮겼습니다.
  • 음성·영상·화면 공유. Agora로 방의 음성·영상과 화면 공유를 연결했습니다. Windows 화면을 공유할 때 컴퓨터 소리를 함께 보내도록 했고, Android는 공유 중 다른 앱으로 전환해도 작은 창에서 방 연결을 유지하도록 했습니다.
  • 그림판과 상담 기록. 그림판의 획과 펜 권한을 동기화했습니다. 큰 그림판의 기존 획은 늦게 온 참가자에게 묶어서 전달해, 개별 획을 다시 보내는 과정에서 화면이 비던 문제를 고쳤습니다. 상담 기록 중에 입장한 사람에게도 동의 안내를 보내고, 동의 전 음성은 축어록에서 제외했습니다.
  • 심리검사와 방 안 스마트폰. 상담사가 내담자의 검사 진행을 함께 보고 결과지를 열 수 있게 했습니다. Windows 상담사와 Android 내담자로 문장완성검사의 실시간 보기 흐름을 확인했습니다. 스마트폰 화면에는 기분 기록, 상담 일정, 마음 호흡을 넣었습니다.
  • AI 비서·웹 검색. 앱에서 서버를 통해 질문·검색 결과를 받고 답변 출처를 표시했습니다. 비서가 상담 도구를 열 수 있게 하되 공지나 채팅을 보낼 때는 확인을 받도록 했습니다. 첫 사용 동의, 답변 신고와 서버 동의 기록도 연결했습니다.
  • 아바타 동작 인식. 카메라 입력으로 표정, 상반신, 전신 동작을 아바타에 적용했습니다. 모바일에서는 추론 실행기를 TFLite로 바꿔 동작 인식 처리 속도를 개선했습니다.

상담 요약에서 동의와 결과를 나눈 이유

축어록 기록과 외부 AI 요약의 동의를 따로 받도록 정했습니다. 요약은 모든 참가자가 동의할 때만 요청하고, 이미 기록 중인 방에 늦게 들어온 사람에게도 같은 선택지를 보여 줬습니다. 축어록과 결과는 상담사 기기에 보관합니다.

짧은 마이크 확인 대화에서 모델 호출은 성공했지만 상담 항목이 비어 앱이 실패로 표시한 경우가 있었습니다. 근거가 없는 상담 항목은 비워 두고, 실제로 오간 말만 짧게 요약하도록 지시를 고쳤습니다. 앱에는 요약할 상담 내용이 없는 경우를 따로 표시하고, 개발 서버에서 짧은 시험 대화로 결과를 확인했습니다.

검증과 전환

기존 앱에서 지켜야 할 API 계약과 서버·관리자 사이트부터 바꾸는 전환·원복 순서를 제가 정했습니다. Claude Code에는 구현과 테스트 작성을 맡기고, EditMode로 앱의 규칙을, PlayMode로 의존성과 씬 연결을 확인했습니다. 수정 범위와 확인 항목을 작업마다 문서에 남기고 브랜치와 PR을 하나로 묶었습니다. 개발 빌드에서 Windows 상담사와 Android 내담자로 같은 방에 들어가 신고·차단과 동의 화면을 확인했습니다.

11월 18일 운영 서버와 관리자 사이트를 먼저 배포했습니다. 이전 서버 이미지와 원복 절차를 마련하고 기존 앱에서 로그인과 상담실 입장을 확인했습니다. 사용자용 운영 웹과 새 Windows 앱 전환은 이후 출시 작업으로 남았습니다. 11월 22일 기록 기준으로 iOS·macOS는 App Store 심사를 통과해 출시 대기 중이었고, Android는 Google Play 심사 중이었습니다.

상담 링크부터 새 앱까지

새 웹의 예약창에서 상담 시작·종료 시각을 분 단위로 직접 입력하거나 선택할 수 있게 만들고, 같은 입력 흐름을 브라우저 회귀 검사에 추가했습니다. 런처에서는 새 상담 링크를 별도로 받아 기존 앱용 링크와 충돌하지 않게 했습니다. 이미 앱이 실행 중이라면 다시 띄우는 대신 입장 링크를 전달하고, 원래 실행의 로그를 보존하도록 수정했습니다.

요약

새 Unity 앱을 설계·구현했습니다. 기존 Node.js 서버는 구 앱과 호환되게 개선했고, React 웹을 새로 개발하고 Electron 런처의 상담실 입장 연동을 손봤습니다. 2026년 11월 운영 서버와 관리자 사이트를 먼저 전환했습니다.

  • 기존 Unity 앱의 화면 공유·화상 채팅·그림판 개발과 PC·모바일 배포
  • 2026년 새 Unity 앱과 React 웹 개발, 기존 서버와 Electron 런처 개선
  • 원복 경로를 준비해 운영 서버·관리자 사이트를 먼저 전환하고 구 앱을 점검
  • EditMode·PlayMode 테스트, Windows와 Android에서 같은 상담실 접속과 동의 흐름 확인

초기 개발과 출시

작업 기록과 화면 보기

2021년 입사 후 MetaForest의 Unity 클라이언트를 개발했습니다. 설치 프로그램과 업데이터를 만들고 Android·iOS 출시를 맡았습니다. 이후 화상 채팅, 그림판, 상담 녹취를 개발하고 Unity 6와 Vivox로 옮기는 작업에 참여했습니다.

초기 개발 배경

메타포레스트는 상담자와 내담자가 익명의 아바타로 만나는 메타버스 심리상담 플랫폼입니다. 2021년 7월 입사했고, 10월 27일 「프로그램에 대한 중요 문제점」 분석 문서를 쓰면서 첫 작업 기록이 시작됩니다. 10월 29일 고○대에 첫 Setup 파일을 배포했습니다. 12월 31일 스프린트 1 빌드로 첫 다인원 파일럿 QA를 했습니다. 아래는 남아 있는 작업 기록을 연도별로 정리한 것입니다.

2021: 입사 첫해

  • 10월 폴리곤 수·프레임 드랍 원인·음성 이슈를 정리한 문제점 분석 문서와 최적화 기록을 썼고, 10월 29일 고○대에 첫 Setup 파일을, 11월 13일 물 교육 프로그램 빌드를 배포했습니다. 기관별 APPVERSION(기관 코드 4종)을 분리하는 버전관리 체계를 잡았습니다.
  • 서울교대 표정인식용 캐릭터 6개, 호서대 메타버스 물 교육 프로그램, Photon 100 CCU를 GameVersion으로 나누는 설정.
  • 0.1v 최적화, 예외 처리, IK 오류, 경고 30개 트러블슈팅. Adobe Character Animator 같은 신기술 테스트.
  • 자체 install 모듈과 update 모듈(WPF 런처)을 만들었습니다. Google Drive의 100MB 직접 다운로드 제한을 OneDrive 직링크로 우회하고, 런처에서 소개 영상을 재생하게 했으며, 설치·바로가기·업데이트 흐름을 QA 체크리스트로 검증했습니다. 이후 4년간 PC 배포는 이 인스톨러·업데이터를 통해 나갔습니다.
  • 12월 말 화면공유 모듈에 착수했습니다. WebRTC 연결, 가상 카메라 설치 스크립트, Photon RPC로 화면 소유권 제어, URP 텍스처 이슈, PC 3대 멀티 테스트까지 진행 기록이 남아 있습니다.

2022: 스프린트와 첫 운영·트라이얼

  • 1월 스프린트 1 통합과 긴급배포 시스템 통합, 상담실별 화면공유 디스플레이, 학교별 계정. 2월부터 표정→애니메이션, 푸시투톡, Photon Voice 개별 음량을 맡아 이후 음성·표정 전반을 담당했습니다.
  • 2~3월 화면공유 모듈(해상도, 오너 종료 처리, 세부 기능)과 인스톨러 개선(가상 카메라 설치 방식 변경), 스프린트 2 버그 수십 건. 3월 8일 인스톨러 1.5.2를 고○대·울○대·계○대에 배포했고, 3월 24일 0.1.0 업데이트(음성 필터 개선, 해상도 기본값, 복도·개인상담실 인테리어, 기관 커스터마이징)를 냈습니다.
  • 4~5월 힐링포레스트 맵 기능, 로드 밸런싱, 캐릭터 추가, 버그리포트 기능, 조작감. 5월 13일 SPRINT 1 킥오프로 2주 스프린트 체계가 시작돼 2023년 4월 SPRINT 21까지 이어졌습니다. 6월 8일 0.5.0 업데이트: 포레스트 맵, 새 아바타, 시점 선택, 내 아바타 표정 보기, 조작 방식 선택, 지도.
  • 6~8월 외부 트라이얼 버전을 만들어 상담센터 2곳·한○대·울○대·○○교육지원청·미국 U○○L에 코드별로 배포했고, 고○대는 운영 버전으로 올렸습니다. 모바일 버전(1·3인칭 카메라, 조이스틱)을 시작했고 폴리곤을 줄여 최적화했습니다.
  • 9월 음성·화면공유 버그를 몰아서 잡고 모바일 출시 구현. 11~12월 Addressables 도입(PC·모바일), 인스톨러·화면공유 프로세스 개선, Photon Voice 버전업, 모바일 운영버전 배포, Android 인앱 업데이트, Mac 호환 예외 처리, iOS 설정·배포. 11월 30일 음성 모듈 교체 버전을 직접 공지했습니다.

클라이언트 운영 환경

운영 중인 메타버스 상담 클라이언트(Unity)입니다. 음성은 Agora, 룸 동기화는 Photon, 코드는 Plastic SCM으로 관리합니다.

상담 중 음성이 끊기던 문제

  • 증상: 상담 중 음성이 30초 동안 끊기는 일이 31분에 6회.
  • 처음 의심한 것: Agora. 하지만 로그를 보니 Photon의 순간적인 끊김(PlayerTtl=0) 때마다 OnPlayerLeftRoom에서 즉시 LeaveChannel을 호출하고 있었습니다. 1초짜리 끊김이 30초짜리 음성 두절로 증폭된 것입니다.
  • 수정: 판정 소스를 바꾸는 게 아니라 디바운스였습니다. 상대 퇴장 시 즉시 LeaveChannel 대신 유예 후 퇴장, 유예 중 복귀하면 예약 퇴장을 취소합니다.
  • 유예 15초 → 45초. 8월 6일 장애에서 두절은 회당 2938초였습니다. 음성 채널에 다시 들어가는 데 걸린 58초를 빼면 참가자가 돌아오는 데 약 21~33초가 걸렸습니다. 관측된 사례를 기준으로 유예를 늘렸습니다. 당시 기록은 패치 구현까지입니다.
  • 같이 잡은 것: 재입장 중 JoinRoom이 실패하면 로딩 화면에 영구히 갇히던 문제. 원인은 blockOFFLoading을 켠 채 씬 로드를 무한 WaitUntil로 기다리던 코루틴이었고, 재입장 코루틴 회수(AbortRejoin)와 타임아웃(로비 15초·씬 30초)으로 고쳤습니다.

한 명만 남은 방의 음성 비용

2명 이상일 때만 음성 채널을 유지하도록 바꿨습니다. 혼자 있는 방에서도 채널이 열려 있던 과금을 없앴습니다. 중복 세션의 진짜 원인은 클라이언트가 아니라 백엔드 webhook의 레이스였고, 이는 백엔드에서 따로 고쳤습니다.

클라이언트 보안 점검

클라이언트에 남아 있던 보안 항목을 한 브랜치에서 정리했습니다. 진단 로그에 비밀값이 그대로 실리던 것은 로그를 일괄로 끄는 대신 값만 마스킹해서 막았습니다. 장애 원인 규명에 쓰던 진단 수단을 함께 잃지 않기 위해서였습니다. 빌드 산출물에 비밀값이 섞여 나가던 경로는 제거하고, 다시 켤 때 서버를 거치도록 경로를 남겼습니다. 쓰이지 않지만 되살아나면 운영 빌드를 잘못된 곳으로 보낼 수 있던 죽은 코드도 지웠습니다.

개별 항목의 내용은 지금도 사용자 기기에 설치된 앱과 이어져 있어 적지 않습니다.

그 밖에

런처 제작 배경

MetaForest는 Unity 클라이언트로 접속하는 메타버스 심리상담 플랫폼입니다. 기존 런처는 WPF(Windows 전용)였고, 상담사·내담자 역할별 기능이 런처에 없어 웹과 앱을 오가야 했습니다.

만든 것

  • Windows + macOS 런처. 로그인(ID·카카오·네이버·구글·애플), 역할별 실기능 탭(채팅·상담 내역·상담실 예약·내담자 관리·AI 상담 내역), 홈 뉴스·공지.
  • 데스크톱 알림, 트레이 상주, 다국어 5종. 런처 세션을 게임 클라이언트에 주입해 재로그인 없이 실행합니다.
  • 다운로드 이어받기, Windows CI 빌드(GitHub Actions), 자동 업데이트 피드.

배포 채널 이전 (2026.08)

  1. S3 버킷 + CloudFront 배포(cdn 서브도메인)를 구성했습니다.
  2. 런처 다운로드 경로를 CDN으로 전환하고, 파일을 6분할해 병렬로 받은 뒤 평면 설치합니다.
  3. 사용자 안내 프로그램을 만들고, 사이트 다운로드 버튼을 CDN 고정 이름으로 전환했습니다.
  4. 런처에 이전 WPF 런처(MSI) 제거 기능을 넣어 사용자가 손대지 않아도 마이그레이션되게 했습니다.

트러블슈팅: 업데이트가 “가끔” 실패하던 문제

증상은 새 버전이 있는데 런처가 못 찾거나 낡은 파일을 받는 것이었습니다. 서버와 CDN 캐시를 먼저 의심했지만, 실제 원인 후보는 Electron net.fetch의 HTTP 캐시 무효화 누락이었습니다. 피드 요청에 캐시 무효화를 넣은 v1.0.4를 배포한 뒤 재현이 사라졌습니다. 이 과정에서 관련 PR 4건을 머지·배포·검증했습니다.

런처 작업에서 배운 것

  • 코드서명: EV 인증서는 SmartScreen에 이점이 없고(MS 공식), 한국 법인도 Azure Artifact Signing을 쓸 수 있으며 electron-builder가 이미 지원합니다.
  • 오브젝트 스토리지 업로드 함정: aws-cli v2의 체크섬 기본값 때문에 PutObject만 AccessDenied가 났고, when_required로 해결했습니다.

운영판과 새 앱이 함께 설치된 시기에 기존 링크는 기존 앱으로 가게 두고, 새 상담 링크만 런처에서 받도록 분리했습니다. 이미 열린 클라이언트에 입장 링크를 전달할 때 원래 실행 로그가 잘리는 문제는 별도 로그로 해결했습니다. 개발 런처와 운영 업데이트 채널을 나눠 설치와 방 입장 흐름을 점검할 수 있게 했습니다.

작업 기록과 화면 보기

상담 일정을 바꿔도 입장 링크 만료일이 바뀌지 않던 오류와 예약 화면의 버그 네 건을 고쳤습니다. 오래된 DB 컬럼이 만든 문제를 정리하고, 산하 기관 관리와 Agora 비용 확인 기능을 추가했습니다.

웹·백엔드 운영 환경

MetaForest 웹(예약·기관 관리·상담 기록)과 Node.js 백엔드입니다. 단일 EC2에 dev/prod 컨테이너로 올라갑니다.

컬럼 하나가 만든 세 가지 증상

AI 상담이 “비활성화”로 보이고, SNS 로그인이 튕기고, 기본 기관이 잘못 표시되는 세 가지 신고가 따로 들어왔는데 원인은 전부 기존 기관 연결 정보였습니다. 코드를 고치고 영향받은 계정 정보를 교정했습니다. 죽은 조건(|| 상수)은 되살리면 깨져서 제거만 했습니다. 회귀 0을 실측했습니다.

예약 화면 버그 4건

PC 날짜 달력(.dateArrow pointer-events), 채팅 링크 다중 기관 LNB(세션 복구 회귀), 날짜칸 autocomplete, 모바일 예약 기관 select 미채움. 처음엔 세션 복구 회귀로 짚었지만 실제 핵심은 예약 모달 select 미채움이었습니다. 오진단을 기록으로 남겼습니다.

캐시 정책과 그 밖에

  • 배포 직후 옛 JS가 보이던 문제를 쿼리 버전(?v=) + html no-cache + js/css 1일 캐시로 정리했습니다. 배포 도구 쪽 PR과 함께 dev·prod 라이브.
  • 산하 기관 계층 기능(교육청 산하 기관 매핑), Agora webhook 기반 음성 비용 측정 페이지(webhook 중복 세션 레이스 수정 포함).

운영 장애를 끝까지 확인

일정 변경 문자가 이미 사용할 수 없는 상담 링크를 보내던 문제를 조사했습니다. 새 링크 생성과 이전 토큰 만료를 예약 변경에서 함께 처리하도록 고쳤습니다. 테스트 페이지에서 성공하는지만 보지 않고 실제 배포본의 예약 변경, 발송된 링크, 앱 입장까지 이어서 확인했습니다. 기관 코드가 남아 있던 레거시 계정은 로그인과 상담 권한 판정이 함께 어긋나는 원인을 추적해 데이터와 코드 양쪽을 정리했습니다.
