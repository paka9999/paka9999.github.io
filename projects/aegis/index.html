맡은 역할

AEGIS는 외부 AI 서비스에 오가는 요청과 응답을 검사하는 보안 게이트웨이입니다. 회사의 GS 1등급 인증 과정에서 시험 결함 수정에 참여했고, 금융권 도입에서는 개인정보 탐지와 운영 화면을 개선했습니다. 이후 Rust 프록시를 맡아 AI 클라이언트 연동과 배포 전 회귀 점검을 개발했습니다.

작업 현황

  • 2026.06 GS 인증 시험 결함 후속 수정
  • 2026.08 – 09 금융권 구축: 접근 권한, 감사 기록, 한국어 개인정보 탐지, 판정 로그·조직 관리·정책 백업 화면
  • 2026.10 – 11 AI 서비스 20여 종의 요청 형식 대응, 현장(HTTP/1.1)과 개발(HTTP/2) 두 경로의 동작 맞추기, 회귀 점검 도구, 폐쇄망 현장 패치
  • 지금 (2026.11) 금융권 현장에서 운영 중이며 정기 패치와 운영 요청을 처리하고 있습니다.

실제로 차단되는 화면

위 사진은 시험 환경에서 AEGIS가 개인정보가 담긴 요청을 막고 클라이언트 화면에 차단 안내를 표시하는 장면입니다. 테스트에 사용한 이름과 식별번호는 가렸습니다.

서비스마다 요청과 응답 형식이 다릅니다. 시험 환경에서 웹·데스크톱·CLI의 요청을 비교하고, Gemini·Codex·Cursor가 정책 차단을 각 클라이언트에서 표시할 수 있도록 연동했습니다.

접근 권한과 감사 기록

역할에 따른 관리자 권한을 공통 검사로 묶고, 역할별로 허용된 동작을 회귀 테스트에 추가했습니다. 계정·권한·관리자 설정이 바뀌면 누가 어떤 작업을 했는지 감사 로그에서 볼 수 있게 했습니다.

한국어 개인정보 탐지와 차단 안내

한국어 텍스트의 개인정보 탐지와 마스킹을 보강하고, 일반 업무 문장이 불필요하게 가려지는 경우를 줄였습니다. 일부 AI 채팅 화면에서 일반 오류로만 보이던 차단 결과는 대화 안에서 정책 안내로 표시되게 수정했습니다.

두 경로 맞추기와 회귀 점검

현장과 개발 환경에서 HTTP/1.1과 HTTP/2의 동작을 비교했습니다. 경로에 따라 차이가 나던 정책 판정, 차단 안내, 기록 처리를 공통 코드로 옮겼습니다.

반복 검증을 위해 Python 도구를 만들었습니다. 시험 요청을 서비스와 경로별로 보내고, 정책 판정·모의 서버에 도달한 요청·클라이언트 응답을 한 결과로 대조합니다. 이전 실행과 달라진 항목을 표시해 한 서비스를 고쳤을 때 다른 경로에 영향이 있는지 확인했습니다. Claude Code를 구현에 활용하고 실제 요청을 재현해 변경을 검토했습니다.

폐쇄망 현장 패치

한 현장에서는 패치 키트를 직접 만들고, 같은 버전의 시험 서버에서 교체와 원복을 리허설한 뒤 현장에 적용했습니다. 리허설에서 디스크 공간이 부족하면 교체가 멈출 수 있다는 점을 찾아, 기존 서비스를 내리기 전에 용량을 확인하도록 작업 절차를 고쳤습니다. 다른 현장에서는 동료가 만든 키트의 반입 파일과 무결성을 확인하고 적용 절차를 지원했습니다.

운영 화면과 검증

판정 로그에 위험 유형·등급·AI 서비스 필터를 넣고 기간 조회를 정리했습니다. 조직 관리와 정책 백업·복원 화면을 만들었고, 현장 적용 전 확인한 항목과 설치 후 운영 절차를 문서에 남겼습니다.

요약

GS 인증 결함 대응과 금융권 QA를 거쳐 Rust 프록시를 맡았습니다. AI 서비스별 응답과 HTTP 경로 간 동작을 맞추고, 정책 판정·클라이언트 응답·기록을 대조하는 Python 점검기를 만들었습니다. 금융권 폐쇄망 패치는 교체와 원복을 리허설한 뒤 적용을 지원했습니다.

  • 웹·데스크톱·CLI로 쓰는 AI 클라이언트에서 정책 차단을 대화 안에 표시
  • HTTP 경로 간 정책 동작을 맞추고 Python 회귀 점검 도구 개발
  • 감사 기록·한국어 개인정보 탐지 개선, 조직 관리와 정책 백업·복원
  • 폐쇄망 패치 키트 제작·리허설과 별도 현장의 반입·적용 지원
