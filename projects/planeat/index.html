Oracle Cloud 운영 서버와 관리자 페이지

1. Oracle Cloud 운영 서버와 관리자 페이지

Oracle Cloud에서 Python·SQLite 운영 서비스를 구동하고 UGS Cloud Code로 Unity 앱을 연결했습니다. 공지와 보상 우편은 앱에 표시하고, 플레이 기록과 서버 거래는 관리자 페이지에서 확인할 수 있게 했습니다.

운영 개요와 공지·이벤트 화면은 실제 관리자 UI를 로컬 샘플 데이터로 실행해 캡처했습니다.

게임 방식

가상 조이스틱으로 행성을 움직여 소행성을 궤도에 모읍니다. 공전하는 소행성으로 가까운 적을 타격하고, 투척으로 떨어진 적을 노립니다. 전투 중 레벨이 오르면 강화 카드에서 이번 판에 적용할 효과를 고릅니다. 스킬과 코어를 조합해 다섯 은하의 보스에 도전합니다.

Unity 클라이언트 개발

  • 행성 이동과 카메라. 행성 모델과 추적 카메라에 같은 보간 좌표를 적용해 화면 떨림을 줄였습니다. 전투 판정과 입력 기록은 기존 물리 좌표를 사용합니다.
  • 보스 공격과 위험 구역. 5개 은하의 보스 패턴 50개에 공격 효과를 보완했습니다. 태양 플레어는 경고 범위와 실제 불꽃이 같은 영역에 나타나도록 맞췄습니다. 오프라인 Android 검증 빌드에서 패턴을 일반·강화로 나눠 100가지 연출을 재생해 확인했습니다.
  • 보스 첫 등장 때의 끊김. Unity Profiler로 화면이 순간 멈추는 구간을 찾아, 보스 효과를 전투 전에 로딩 화면에서 미리 준비하도록 바꿨습니다.
  • 전투 HUD와 클리어 결과. 플레이 중 언어를 바꾸면 열린 HUD의 번역도 갱신되게 했습니다. 설정 창이 열려 있을 때는 튜토리얼 가이드와 전투 입력이 끼어들지 않도록 했습니다. 서버의 진행 정보가 늦게 도착해도 열려 있는 결과 창에서 순위와 다음 행성 버튼이 바뀌도록 연결했습니다.

게임 백엔드와 UGS

  • 계정과 저장. Unity Gaming Services의 로그인과 Cloud Save를 연결했습니다. Android에서 실제 Google 계정 로그인 후 클라우드 진행 기록을 내려받아 복원하는 흐름을 확인했습니다. 순위표에는 UGS Leaderboards를 사용했고, 회원 탈퇴 경로에서 해당 플레이어 점수도 정리하도록 연결했습니다.
  • 운영 서버와 관리자 도구. Python·SQLite로 만든 운영 서비스를 Oracle Cloud에 올리고 Unity 앱과 UGS Cloud Code를 연결했습니다. 관리자 페이지에서 플레이 기록과 전투 정산, 계정별 재화·구매 내역을 확인하도록 했습니다. 공지·이벤트, 보상 우편과 쿠폰 처리도 연결하고 서버 배포·백업·원복 절차를 문서로 남겼습니다. 운영 관리자 화면
  • 재화 원장. 코인·별조각 잔액, 상품 지급, 스킨 소유권을 서버에서 처리하도록 옮겼습니다. 코어 구매·강화와 연구, 하트, 출석·미션, 방치 보상도 연결했습니다. 차감과 지급은 같은 거래로 확정하고, 재요청에는 기존 처리 결과를 돌려주도록 했습니다.

상점과 인앱 현금 결제

  • 상품과 구매 화면. Google Play에서 상품의 실제 가격을 받아 표시하고, 무료 보상·재화 상품·계정당 한 번 살 수 있는 첫 탐험 패키지를 상점에서 구분했습니다.
  • 결제 검증과 복구. Unity에서 받은 영수증을 Cloud Code로 서버에 보내 Google Play 구매 상태를 확인했습니다. 지급은 주문당 한 번 기록하고, 결제창을 닫거나 앱이 재실행되면 구매 내역에서 처리 결과를 다시 확인할 수 있게 했습니다. 구매 승인 대기 안내와 계정별 구매 내역 혼선도 수정했습니다.
  • 실제 검증. Android 내부 테스트에서 소액 실제 청구 1건을 Google Play 주문, 서버 영수증, 별조각 지급 기록과 각각 대조했습니다. 다음 내부 빌드에서 구매 내역을 다시 확인했을 때 잔액과 지급 건수가 그대로였습니다. iOS의 서버 연동 실기 확인은 팀원이 Sandbox로 검증했습니다.
  • 보상형 광고. 첫 광고를 상점에서 미리 준비하도록 하고, 광고 종료 뒤 서버 지급과 상점 잔액이 일치하는지 확인했습니다. 앱 재실행 뒤에도 같은 광고에 추가 지급이 없었습니다.
  • 팀 공통 보상 검사. 출석·미션·상점의 무료 보상에 공통 지급 경로를 적용했습니다. 재시도 중복 지급과 과거 주문 복구가 현재 결제에 영향을 주는 문제를 확인할 수 있도록, 커밋과 GitHub Actions에서 같은 검사를 실행하게 했습니다.

Cloudflare R2와 리소스 업데이트

Unity Addressables를 Cloudflare R2에 연결해 도움말과 스킨·전투 모델·음향을 앱과 따로 내려받게 했습니다. 새 묶음을 검증한 뒤 적용하고, 다운로드가 실패하면 내장 리소스로 시작할 수 있게 했습니다. Android 검증용 빌드에서는 두 기기로 새 파일 수신과 실패 뒤 복구를 확인했습니다.

전투 보상 정산

초기에는 서버에서 전투 입력을 재생해 결과를 대조하는 흐름을 만들었습니다. 이후 새 전투의 운영 기본값은 서버가 제출된 기록을 규칙으로 검사하고 보상을 계산해 같은 요청에서 정산하는 방식으로 전환했습니다. 이미 발급된 이전 결과는 복구할 수 있게 보존했습니다.

코딩 에이전트와 팀 개발

행성과 카메라가 떨리는 문제를 고칠 때, 표시 위치만 바꾸고 전투 판정과 입력 기록에 쓰는 물리 좌표는 유지한다는 조건을 Claude Code에 줬습니다. 작업 계획과 코드 변경을 검토하고, 변경 이유와 같은 장면에서 다시 확인하는 절차를 PR에 남겼습니다.

팀이 쓰는 설계·QA 문서를 Claude Code에도 읽혔습니다. 출석·미션·상점에 공통으로 적용되는 보상 규칙은 중복 지급과 구매 복구를 확인하는 검사로 만들어, 커밋 전과 CI에서 팀원과 각자의 에이전트가 같은 기준으로 확인합니다. 직접 만든 Discord 미팅 봇은 정기회의를 전사해 결정과 할 일을 팀 저장소에 남깁니다.

첫 실행과 보상형 광고

새 설치에서 로비로 진입하기 전에 리소스 준비가 멈추거나 앱이 종료되는 문제를 추적했습니다. 초기 리소스 확인과 실패 후 다시 시도하는 흐름을 보완한 뒤 새 게스트 두 계정에서 첫 실행과 로비 진입을 확인했습니다. 광고는 상점에 들어갈 때 미리 로드하되 실제 시청 요청에서만 보상 처리를 시작하도록 나눴습니다. 수정 빌드를 실제 Android 기기에서 실행해 준비된 광고가 첫 탭에 표시되고, 시청 뒤 서버 지급이 한 번만 기록되는 것을 확인했습니다. 이후 국가 조회 실패와 재시도 흐름을 보완해 Android·iOS 코드 검사에서 확인했습니다.

요약

행성을 움직여 소행성을 모으는 3인 팀 게임입니다. Unity에서 행성 이동과 카메라, 보스 공격 연출, 전투 HUD와 결과 화면을 개선했습니다. Oracle Cloud 운영 서버와 관리자 웹을 만들고 UGS와 결제·광고, 게임 리소스 배포를 연결했습니다.

  • 행성·카메라 보간, 보스 공격 연출, 전투 HUD와 클리어 결과 개선
  • UGS 로그인·Cloud Save 복원과 Cloud Code를 통한 운영 서버 연동
  • 서버 지갑과 상점 거래, 스킨 소유권, 코어·연구·출석·미션 보상 처리 구현
  • Google Play 결제 영수증 검증·중복 지급 방지와 구매 내역 복구 구현, Android 소액 실결제 검증
  • Cloudflare R2와 Addressables를 연결해 스킨·전투 모델·음향을 다운로드하고 실패 시 기본 리소스로 복구
