대학 AAC 챗봇 백엔드Python · RAG · OCR

인계받은 챗봇에 플랜별 한도와 rate-limit 엔진을 설계해 배포했습니다

역할
백엔드 개발·배포
기간
2026.06
상태
prod 운영 중
스택
Python, Node.js, RAG, ECR, EC2

배경

대학의 AAC(보완대체의사소통) 챗봇 백엔드를 인계받았습니다. 프론트(Node)와 RAG API(Python)가 EC2에 따로 올라가는 구조였습니다.

만든 것

  • 플랜 엔진: Basic/Plus/Premium 월 한도 + rate-limit. 챗과 OCR을 각각 카운트하고, OCR은 Vision 호출 직전에 plan.consume으로 차단합니다.
  • RAG 직접 호출 차단(내부 시크릿 헤더), /health의 실제 OpenAI 검증, 하이드레이션 오류·챗 쿼터 프론트 반영.
  • 테스트 26개(vitest), requirements 고정.

배포

CI 결제가 막힌 상황이라 수동 SSH 배포 체계를 정리했습니다. 프론트는 ECR amd64 빌드 후 컨테이너 교체, RAG API는 EC2 네이티브 빌드.

남긴 것

보안 감사에서 공지 저장형 XSS(HIGH), 무인증 사용량 로그, CORS·로그인 rate-limit, JWT 폴백 같은 후속 과제를 정리해 넘겼습니다.

요약

보완대체의사소통(AAC) 챗봇 백엔드를 인계받아 Basic/Plus/Premium 플랜과 월 한도·rate-limit 엔진을 넣고, 내부 RAG API 직접 호출을 차단했습니다. CI가 막힌 상황에서 수동 배포 체계를 정리하고 보안 감사 후속 과제를 도출했습니다.

  • Basic/Plus/Premium 플랜 한도·OCR 쿼터·내부 RAG 직접 호출 차단
  • 수동 SSH 배포 체계: 프론트는 ECR 빌드 후 컨테이너 교체, RAG API는 EC2 네이티브 빌드
  • 보안 감사: 공지 저장형 XSS(HIGH)·무인증 사용량 로그·CORS·로그인 rate-limit 후속 도출
