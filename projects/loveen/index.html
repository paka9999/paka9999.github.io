배경

“둘만의 관계를 기록하고, 챙기고, 함께 움직이는 폐쇄형 공간.” 메신저가 입구, 아카이빙이 락인, 캘린더가 복귀 트리거, 지도가 확장이라는 가설로 커플 앱을 기획했습니다.

만든 것

  • 문서 10종: 기획안, 출시 로드맵, 기술 아키텍처, 핵심 설계 리스크(이별 플로우·데이터 모델·온보딩), Phase 1 기능명세, 설계 결정 기록(E2E·삭제 정책·최소 OS), ERD, 화면 흐름도, API 명세(REST + WebSocket 이벤트), 개발 일정·인력 산정.
  • 모노레포: NestJS 10 + Prisma 5 + PostgreSQL 16 + Redis 7 + MinIO + coturn 백엔드, Socket.IO 게이트웨이(채팅·함께 그리기·통화 시그널링), SwiftUI iOS(iOS 16+), Kotlin/Compose Android(minSdk 26).
  • Phase 1 와이어프레임(HTML)과 9슬라이드 피칭 덱.

기술적 결정

  • 네이티브 두 벌(Swift + Kotlin)을 택했습니다. 메신저·통화·사진 아카이빙은 플랫폼 API 의존이 커서, 크로스플랫폼의 이점보다 비용이 크다고 판단했습니다.
  • 이별 플로우를 먼저 설계했습니다. 커플 앱에서 가장 어려운 엣지케이스라 데이터 모델 단계에서 정했습니다.

상태

기획·설계 완료, Phase 1 구현 진행 중. HANDOFF 문서가 현재 상태의 단일 출처입니다.

요약

메신저·아카이빙·캘린더·지도 4개 기둥. 기획안·ERD·API 명세·ADR 등 문서 10종과 NestJS 백엔드, SwiftUI iOS, Compose Android 모노레포.

  • 문서 10종: 기획안·로드맵·아키텍처·핵심 설계 리스크·기능명세·ADR·ERD·IA·API 명세·공수 산정
  • NestJS 10 + Prisma + PostgreSQL + Redis + MinIO + coturn, Socket.IO 게이트웨이
  • 이별(관계 종료) 플로우를 데이터 모델 단계에서 먼저 설계
