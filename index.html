Unity 클라이언트 프로그래머 · YATAV · 2021 – 현재

강성주Seongju Kang

5년간 운영한 Unity 클라이언트, 3인 팀 모바일 게임, 그리고 제품과 도구 양쪽에 쓰는 AI.

Unity 클라이언트 프로그래머입니다. YATAV에서 메타버스 상담 플랫폼의 Unity 클라이언트를 5년간 만들고 운영했습니다. PC·Android·iOS·macOS 동시 배포, Photon·Vivox·Agora·Addressables 위의 실시간 기능, 인스톨러부터 CDN까지의 배포 파이프라인이 제 몫이었습니다. 지금은 AI를 제품 안(AI NPC, STT 축어록, AI 요약)과 개발 과정 양쪽에 씁니다. 에이전트를 직접 만들었고, 토큰 비용을 줄이려 로컬 모델로 옮기는 작업과 Unity 전용 빌드 자동화도 직접 해봤습니다. 3인 팀으로 모바일 게임 PlanEat을 만들어 Google Play 출시를 준비하고 있습니다.

03

강점

  • 01운영 중인 서비스에서 기반을 바꿉니다.Unity 2021 → 6, Photon PUN → Fusion, 음성 Photon Voice → Vivox → Agora를 사용자를 끊지 않고 교체했습니다. PC·모바일 QA 리스트(2023년 8월 출시 때 77건)와 긴급 배포 절차를 먼저 만들어 두었기 때문입니다.
  • 02실시간 모듈을 직접 만듭니다.화면공유(WebRTC + Photon RPC 소유권 제어), 1:1 화상채팅, 그림판 멀티 동기화, 표정 인식, 음성(Agora·Vivox), Photon CCU 분리까지 실시간 기능은 제 몫이었습니다.
  • 03배포 경로를 끝까지 쥡니다.2021년 WPF 인스톨러·업데이터부터 2026년 Electron 런처와 CDN 6분할 병렬 다운로드까지, 4개 플랫폼과 스토어 심사를 한 사람이 배포하고 공지했습니다. 남아공·대만 다운로드 이슈는 서버·스토리지 교체로 풀었습니다.
  • 04증상이 아니라 원인을 고칩니다.음성 두절은 Agora가 아니라 Photon 순간 끊김이 코드에서 30초로 증폭된 것이었고, 런처 업데이트 실패는 서버가 아니라 HTTP 캐시 무효화 누락이었습니다. 실측이 진단을 바꾸면 바뀌었다고 말합니다.
  • 05함께 만드는 쪽으로 일합니다.출시 판단은 PC·모바일 QA 리스트로, 배포 공지는 알려진 문제와 임시 해결책까지 적어 기관 담당자가 바로 대응하게, 다음 사람이 이어받을 수 있게 HANDOFF 문서를 남깁니다.

AI 활용

AI 도구로 코드를 쓰고 검증하는 것은 매일 하는 일입니다. 아래는 말이 아니라 결과물로 보여드릴 수 있는 것들입니다. 코드는 레포에서 그대로 가져왔습니다.

  1. 01에이전트를 직접 만들었다: seongjuclaw

    Python · Claude API · Ollama · 2026.07 –

    무엇
    터미널·파일·웹을 손발로 쓰는 에이전트. 도구 루프, SKILL.md 스킬 시스템, 세션 저장·복원, 로컬 RAG(서버 없이 fastembed), 로컬 모델(Ollama) 전환, 외부 호출을 전부 끊는 폐쇄망 모드, 데스크톱 GUI까지 직접 구현.
    왜
    Claude Code 같은 도구가 안에서 어떻게 도는지 알아야 잘 시킬 수 있다고 봤습니다. 도구 호출 순서, 컨텍스트 관리, 병렬 실행의 안전 조건을 손으로 겪어봤습니다.
    검증
    RAG·툴 루프는 실제 모델로 end-to-end 실행 확인. GUI는 폐쇄망 모드에서 로컬 모델(gemma4 12b)이 파일을 읽고 답하는 것까지 실행해 캡처했습니다(2026.09).

  2. 02토큰 값을 줄이려고 로컬 모델로 옮겼습니다

    Ollama · llama.cpp · vLLM · fastembed · 2026

    왜
    API 호출이 늘수록 비용이 그대로 늘었습니다. 조사·요약·분류처럼 최고 성능이 필요 없는 일은 로컬 모델로 내려도 된다고 보고 옮겼습니다.
    어떻게
    직접 만든 에이전트에 Ollama를 붙여 Claude와 같은 도구 루프 위에서 모델만 바꿔 끼우게 했고, 외부 호출을 전부 끊는 폐쇄망 모드를 넣었습니다. RAG는 서버 없이 fastembed와 numpy로 돌려 임베딩 API도 쓰지 않습니다.
    실무에서
    폐쇄망 AI 제품은 전부 로컬 모델(vLLM·Ollama)로 돌아갑니다. 임베딩을 GPU로 옮겨 첫 응답을 20초에서 1.2초로 줄였고, AI 보안 제품의 판정 모델도 llama.cpp로 로컬에서 띄웠습니다.
    한계
    로컬 9B는 긴 문맥에서 서식이 무너집니다. 그래서 무엇을 로컬에 두고 무엇을 API에 둘지 작업별로 나눕니다.

  3. 03Unity 전용 빌드 자동화를 만들어 봤습니다

    Python · Unity 배치모드 · 2026.08

    왜
    5년간 CI에서 같은 곳에 계속 걸렸습니다. 종료코드가 0인데 빌드는 실패해 있거나, -quit과 테스트 옵션이 충돌하거나, 라이선스 시트가 반납되지 않는 문제였습니다.
    어떻게
    겪어봐야 아는 함정을 먼저 모듈 문서로 쓰고 구현을 에이전트에게 맡겼습니다. 도메인 지식은 사람이 주고 구현 속도는 AI가 내는 방식입니다.
    어디까지
    종료코드를 믿지 않고 빌드 리포트와 로그 신호를 우선하는 판정 로직을 테스트로 고정했습니다. 이 맥에 해당 Unity 버전이 없어 실제 프로젝트로 끝까지 돌려보지는 못했고, 그 구분은 그대로 적어 두었습니다.

  4. 04AI 제품을 QA하고 만들고 운영한다

    AEGIS · 독립지능 · AAC 챗봇 · 2026

    AEGIS
    AI 보안 게이트웨이(AI DLP). GS 인증 결함 후속 수정(결함 1건 = PR 1건), 금융권 구축에서는 납품 전 체크리스트를 실측해 권한 경계·감사 원장·한국어 PII 탐지 결함을 찾아 고쳤습니다.
    독립지능
    폐쇄망 업무용 AI. 출시 전 QA, 게이트웨이 훅·문서 도구 수정(100회 실측 0% → 99%), 죽은 서버를 Jetson 위에 재구축해 도메인 2개 라이브.
    원칙
    에이전트에게 코드는 맡겨도 배포는 맡기지 않습니다. 되돌리기 어려운 동작은 사람이 누릅니다.

AI에게 일을 시킬 때

  • 규칙을 문서로 준다. 레포마다 CLAUDE.md·HANDOFF.md, 에이전트에는 SKILL.md. 무엇을 하지 말아야 하는지가 먼저.
  • 도메인 지식은 내가, 구현은 같이. 겪어봐야 아는 함정은 먼저 써서 준다. 로컬 개발 우회가 켜져 있으면 인증 실패가 조용히 관리자로 떨어진다는 것을 모르면, 권한 시험 결과를 반대로 읽는다.
  • 결과는 다시 확인한다. 빌드·실행·스크린샷·실측. "됐습니다"는 눈으로 본 뒤에만.
  • 되돌리기 어려운 건 사람이. 배포·게시·삭제·결제는 에이전트가 하지 않는다.
