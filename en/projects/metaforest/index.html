My part in the rebuild

I began designing and building the new Unity app in a separate repository in August 2026. I extended the existing Node.js server and began building a React website in September. I added a route in the Electron launcher to pass counseling room links to the new app.

  • Unity. I synchronized session recording state with Photon Fusion 2 so people joining after recording began received the consent prompt. Their audio stayed out of the recording until they consented. I moved maps to on-demand downloads from a CDN.
  • Server and admin site. I preserved API compatibility for the existing app and website while building personal-data access logs, failed-login lockout and deletion tools, and updating the admin screens.
  • New website and launcher. I built counseling room booking and entry pages in React and checked that the new website worked with the launcher in development.

Counseling features I built

  • Room entry and navigation. I connected booking links to the launcher and app, checked room permissions and moved maps to on-demand CDN downloads. I brought entry points, doors, seats and screens into the new client’s themed rooms.
  • Voice, video and screen sharing. I connected room media through Agora and added desktop audio to Windows screen sharing. On Android, picture-in-picture keeps the room connection active when the user switches apps during a share.
  • Whiteboard and session recording. I synchronized strokes and pen ownership. I bundled large boards for late joiners to fix cases where replaying each stroke left the board blank. People who arrived after recording began received a consent prompt, and their audio stayed out of the transcript until they consented.
  • Assessments and the in-room phone. I enabled counselors to follow a client’s assessment live and open the saved results. I checked live sentence-completion assessment viewing with a Windows counselor and an Android client. The virtual phone includes mood check-ins, appointments and breathing exercises.
  • AI assistant and web search. I connected the app to the server for questions, web search and source links. The assistant could open counseling tools but needed confirmation before sending announcements or chat messages. I also wired up first-use consent, answer reporting and server-side consent records.
  • Avatar motion tracking. I mapped face, upper-body and full-body movement from one camera to the avatar and moved inference to TFLite to improve mobile throughput.

Consent and empty results for AI summaries

I separated consent for transcription from consent to send the transcript to an external AI service. The app requests a summary only when everyone agrees and gives late arrivals the same options. The transcript and summary stay on the counselor’s device.

In a short microphone-check conversation, the model returned successfully but left the counseling fields empty, which the app displayed as a failure. I revised the model instructions to summarize only what was said and leave unsupported fields empty. The app now distinguishes insufficient counseling material from an error. I verified the change with a short test dialogue on the development server.

Verification and rollout

I defined the API contract that the existing app needed and planned the server and admin rollout and rollback. I used Claude Code to help implement changes and write tests. EditMode covered application rules and PlayMode checked dependencies and scene wiring. I documented the scope and checks for each round of work and kept it to one branch and pull request. In development builds, I checked reporting, blocking and consent in the same room as a counselor on Windows and a client on Android.

The production server and admin site went live on November 18. I prepared a rollback image and documented the recovery steps, then checked sign-in and room entry in the existing app. The public website cutover and Windows release remained separate release steps. As of November 22, iOS and macOS had passed App Store review and were awaiting release. Android remained in Google Play review.

From a booking link to the new app

I added minute-level time selection and direct entry to the new booking UI and covered both in a browser regression check. The launcher recognizes the new counseling link separately so it can coexist with links for the previous app. If the client is already open, the launcher forwards the room link and keeps the existing session log intact.

Summary

I designed and built the new Unity app, extended the existing Node.js server while keeping older apps compatible, built the React website and updated the Electron launcher’s room links. The production server and admin site went live first in November 2026.

Early development context

MetaForest is a metaverse counseling platform where counselor and client meet as anonymous avatars. I joined in July 2021, and the first work records start on 27 October with an analysis note I wrote on the program’s key problems. The first setup file shipped to Korea University on 29 October. Lessons

  • Own the delivery path. Because the installer/updater and Addressables were ours, regional problems in South Africa and Taiwan were solved by swapping servers and storage.
  • Foundations can be replaced in production. Photon Voice → Vivox and Unity 2021 → 6 went through without cutting users off, thanks to QA lists and an emergency-release routine.
  • A release note lists the known problems too. Notes like 3.1.6’s, with issues and workarounds, were what let institution staff respond.
  • Company outcomes in this period: official adoption by Seoul Wee centers (2023), the Metaverse Innovation Award (2024), the MWC25 GLOMO Award (2025).

2025.11 – 2026.08

Client operations

I tested the Unity 6 client by joining the same counseling room from a PC and a phone.

View work notes and media

I began migrating the existing client to Unity 6 in November 2025. I used AI agents to analyze older code, remove unused features and replace libraries. In August 2026 I traced voice dropouts and implemented a patch. The check-ins record the patch but contain no device verification or production rollout result for it.

Client operations context

A live metaverse counseling client in Unity. Voice runs on Agora, room sync on Photon, source control on Plastic SCM.

Voice dropouts during sessions

  • Symptom: Voice cut out for 30 seconds, six times in 31 minutes.
  • First suspect: Agora. But the logs showed that on every momentary Photon disconnect (PlayerTtl=0), OnPlayerLeftRoom called LeaveChannel immediately. A one-second blip was amplified into a 30-second outage.
  • Patch. I added a 45-second grace period before closing the channel and canceled the scheduled closure when the participant returned. The check-ins record the implementation.

Agora costs in rooms with one user

The voice channel now stays open only with two or more people, removing charges for rooms where someone sat alone. The duplicate-session issue turned out to be a backend webhook race, not the client, and was fixed there.

Also

  • A transcript-summary feature that was unused but still riding along in builds was removed.
  • Speaker indicators froze with five or more participants because Agora reports only the top three speakers. Fixed.

Client security fixes

Security items left in the client were cleaned up on one branch. Secrets that rode along verbatim in diagnostic logs are now masked rather than silenced, so the diagnostics that root-caused the August outage stay available. The paths that let secrets ship inside build output were removed, with a server-side path left for re-enabling. Dead code that would have pointed a production build at the wrong place if revived was deleted.

The individual items are not written up here, because they still connect to app versions installed on users’ devices.

Moving five years of code into a new repository meant a lot of code to read, so I put AI agents on the repetitive parts: reading the old code, clearing unused features, swapping libraries. Results were checked with builds and on real devices, and the remade client shipped to production.

A new repository for the Unity 6 client. My check-ins by month: November Photon swap, OpenCV/Dlib removed for MediaPipe face tracking, animal characters. December lighting rebuilds for eight counseling scenes, SKT plugin removal, the 3.1.6 production release. January Sentry, webview, a MediaPipe upgrade, the start of Android 16 KB page-alignment work, urgent optimization with Cursor. February quick-counsel deep links, automatic Photon region selection, Android video-chat audio fix. March 16 KB alignment solved, face zoom, an NPOT-to-POT converter. April Unity 6000.3.10 → 3.12, voice moved fully to Agora, chat UI rework. May the 3.3.3 hotfix and voice filters. June occupancy gating, speakerphone routing, auto-reconnect. 2026.06 – 2026.08

Launcher and delivery

I built the Windows and macOS launcher and moved installer downloads to a CDN.

View work notes and media

I built a Windows and macOS launcher with sign-in and automatic updates. When I moved distribution to S3 and CloudFront, I added six-way downloads and a migration path from the old launcher.

Launcher context

MetaForest is a metaverse psychological counseling platform accessed through a Unity client. The old launcher was WPF (Windows only), and counselor/client features were missing from it, so users bounced between the web and the app.

Launcher features

  • A launcher for Windows and macOS. Login (ID, Kakao, Naver, Google, Apple), role-based feature tabs (chat, session history, room booking, client management, AI session records), home news and notices.
  • Desktop notifications, tray residency, five languages. The launcher session is injected into the game client so there is no second login.
  • Resumable downloads, Windows CI builds (GitHub Actions), an auto-update feed.

Distribution migration (2026.08)

  1. Set up an S3 bucket with a CloudFront distribution on a cdn subdomain.
  2. Switched launcher downloads to the CDN, splitting files six ways for parallel download and flat install.
  3. Built a user guide program and switched the website’s download buttons to fixed CDN names.
  4. Added removal of the old WPF launcher (MSI) to the launcher itself, so users migrate without touching anything.

Troubleshooting: updates that “sometimes” failed

Symptom: a new version existed, but the launcher could not find it or downloaded stale files. Server and CDN caches were the first suspects, but the actual candidate was a missing HTTP cache invalidation on Electron’s net.fetch. After v1.0.4 shipped cache-busting on the feed request, the failure stopped reproducing. Four related PRs were merged, deployed and verified along the way.

Lessons from the launcher

  • Code signing: EV certificates give no SmartScreen advantage (per Microsoft), and a Korean company can use Azure Artifact Signing, which electron-builder already supports.
  • Object-storage upload trap: aws-cli v2’s default checksum caused AccessDenied only on PutObject; when_required fixed it.

Booking-link compatibility and session logs

While both clients were installed, I kept existing links routed to the prior app and gave the new counseling links a separate launcher path. I separated the log for forwarding a link to an already-running client so it would not truncate the session log. I also separated the development installer and feed from production so we could check installation and entry safely.

2026.05 – 2026.07

Web and backend

I fixed booking and room-link problems and improved organization management.

View work notes and media

Changing a booking could leave the room link with the old expiration time. I fixed that and four booking-screen bugs, traced several issues to a legacy database column, and added tools for managing sub-organizations and tracking Agora costs.

Web and backend context

The MetaForest web app (booking, organization management, session records) and its Node.js backend, running as dev/prod containers on a single EC2 instance.

One column, three symptoms

Three separate reports: AI counseling showing “disabled”, social login bouncing, wrong default organization: all traced to the legacy the legacy organization field. Code fixed, the affected accounts corrected in a full audit. A dead condition (|| constant) broke things when revived, so it was removed rather than restored. Zero regressions measured.

Four booking-screen bugs

Desktop date picker (.dateArrow pointer-events), multi-organization LNB via chat link (session-restore regression), date field autocomplete, and an unfilled organization select in the mobile booking modal. The first diagnosis blamed the session-restore regression; the real core was the unfilled select. The misdiagnosis was written down.

Cache policy and more

  • Stale JS after deploys was resolved with query versioning (?v=), html no-cache and one-day caching for js/css, together with PRs on the deployment tool; live on dev and prod.
  • A sub-organization hierarchy (mapping institutions under an education office) and an Agora webhook-based voice cost page, including a fix for a duplicate-session race in the webhook handler.

Following production fixes through to room entry

I investigated rescheduling notices that sent an unusable room link. I made booking changes update both the new entry link and the expiry of the previous token. I verified the full flow in the deployed build, from changing the booking and opening the sent link to entering the app. I also traced several login and access symptoms to legacy organization assignments and corrected the data as well as the application logic.
