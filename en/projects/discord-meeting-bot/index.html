Discord Meeting Bot

Automatic recording, transcription and summaries for Discord meetings

Role
Design and implementation
Period
2026.07 – 2026.08
Status
In use
Stack
TypeScript, discord.js, Whisper, Claude API

Why

I designed and built a Discord bot so JJJ STUDIO could look up decisions and action items after meetings.

How it works

  1. /watch add <voice channel> registers a channel. When someone joins, the bot joins and starts recording; when everyone leaves, it stops.
  2. The bot receives one audio stream per participant and saves Opus audio as OGG without re-encoding.
  3. Whisper transcribes; Claude extracts a summary, decisions and action items.
  4. The summary embed and the minutes/transcript files are posted to the text channel, and optionally committed to a GitHub repository as meetings/YYYY/MM/*.md through the Contents API: no clone needed.

Stack

Node.js 22 + TypeScript, discord.js v14 + @discordjs/voice, prism-media v2. No privileged intents; STT and summary models are configured via environment variables.

Used in JJJ STUDIO meetings

I connected the bot to the team’s voice channel for regular meetings. It posts the summary, decisions and action items in Discord and commits dated Markdown notes to the team repository for later reference.

Finding and reusing meeting records

I kept mute and video changes from restarting a recording and addressed provider rate limits when transcribing many speaker tracks and reported recording, transcription and summarization progress in the channel. I then added past-meeting lookup, reposting and a question command that uses saved transcripts and minutes.

Summary

I built this Discord bot for JJJ STUDIO’s regular meetings. It records each speaker separately, transcribes the discussion and saves decisions and action items to Discord and the team repository.

  • Separate audio streams preserve speaker attribution
  • Opus audio saved as OGG and minutes committed through the GitHub Contents API
  • STT and summary models are swapped via environment variables
