How it works

Oracle Cloud backend and admin dashboard

1. Oracle Cloud backend and admin dashboard

I ran the Python and SQLite operations service on Oracle Cloud and connected the Unity app through UGS Cloud Code. The client receives notices and reward mail, while the dashboard shows gameplay and server transactions.

The screenshots show the actual operations UI running locally with sample data.

How the game plays

Steer a planet with a virtual joystick and capture asteroids in orbit. Orbiting asteroids hit nearby enemies, and you can throw them at distant targets. When you level up during a run, pick an upgrade from the cards on screen. Combine skills and cores to take on bosses across five galaxies.

Unity client development

  • Planet movement and camera. I reduced jitter by giving the planet model and follow camera the same interpolated position. Combat checks and input recordings still use the physics position.
  • Boss effects and danger zones. I revised the visuals for 50 boss patterns across five galaxies and aligned the solar flare’s fire with its warning area. I checked 100 normal and enhanced visual cases in an offline Android QA build.
  • Hitch when the boss first appears. I used the Unity Profiler to find where the screen briefly froze and moved the boss effects’ first-render preparation to the loading screen.
  • Combat HUD and results. I refreshed HUD translations during play and kept tutorial prompts and combat input out of the settings overlay. I also updated the ranking and next-planet button in the result screen when the server returned progress after the screen was already open.

Game backend and UGS

  • Accounts and saves. I connected Unity Gaming Services login and Cloud Save. On Android I verified that a real Google sign-in could download and restore progress. I used UGS Leaderboards and connected account deletion to removal of the player’s score.
  • Operations backend and admin tools. I deployed the Python and SQLite service on Oracle Cloud and connected the Unity app through UGS Cloud Code. The dashboard shows gameplay, combat settlement, player balances and purchase records. I connected notices, events, reward mail and coupons, and documented deployment, backup and rollback. Operations dashboard
  • Currency ledger. I moved balances, shop grants and skin ownership to the server. I connected core purchases and upgrades, research, energy, attendance, missions and idle rewards. The server settles the cost and grant in one transaction and returns the existing result when a request is retried.

Shop and real-money in-app purchases

  • Catalog and shop. I displayed the live Google Play prices and separated free rewards, currency packs and the one-time First Exploration offer in the shop.
  • Verification and recovery. I sent the Unity purchase receipt through Cloud Code for Google Play verification. The server grants each order once. Players can check the outcome after dismissing the purchase dialog or restarting the app. I also fixed pending-payment messaging and scoped purchase history to the current account.
  • What we verified. One real-money Google Play purchase on an Android internal build matched one verified receipt and one currency grant. Checking purchase history again in the next internal build left the balance and grant count unchanged. A teammate verified the iOS store connection on a device using Sandbox.
  • Rewarded ads. I let the shop prepare the first ad in advance, then compared the server grant and shop balance. Relaunching did not grant the same ad reward again.
  • Shared reward regression checks. I routed daily check-ins, missions and free shop rewards through the same claim flow. Local commits and GitHub Actions run the same checks for duplicate grants after a retry and for restored purchases interfering with a new checkout.

Cloudflare R2 and content updates

I connected Unity Addressables to Cloudflare R2 to ship tips, skins, combat models and audio separately from the app. The app validates a new pack before applying it and can start with built-in assets if the download fails. I checked fresh downloads and recovery on two Android devices using a QA build.

Combat reward settlement

I first implemented server-side replay of combat inputs. For new runs, I later switched the production default to rules-based checks and server-side reward calculation and settlement in the same request. Recovery remains available for previously issued results.

Working with coding agents on the team

To fix planet and camera jitter, I asked Claude Code to change only the rendered positions and keep the physics coordinates used for combat and input logging. I reviewed the plan and diff, then recorded why the change was made and how to reproduce the check in the pull request.

Claude Code reads the same design and QA notes as the team. I turned reward rules shared by attendance, missions and the shop into checks for duplicate grants and purchase recovery. The team and its agents run the same checks before committing and in CI. The Discord bot I built transcribes regular meetings and saves decisions and action items in the team repository.

First launch and rewarded ads

I investigated startup interruptions before players reached the lobby. After revising the initial resource check and retry flow, I checked first launch and lobby entry with two new guest accounts. I separated ad preloading on shop entry from starting the reward transaction on a viewing request. On a physical Android device, I confirmed that a preloaded ad appeared on the first tap and that the server recorded one grant after viewing. I later improved country lookup failure and retry handling and checked those paths in Android and iOS harnesses.

Summary

A three-person mobile game about steering a planet and collecting asteroids. I improved planet movement, the camera, boss effects, combat HUD and results in Unity. I also built the Oracle Cloud game backend and admin console and integrated UGS, purchases, ads and content delivery.

  • Improved planet and camera interpolation, boss visuals, the combat HUD, and the results screen
  • Connected UGS login, Cloud Save recovery, and the game operations backend through Cloud Code
  • Built server-side wallet and shop transactions, skin ownership, upgrades, and recurring rewards
  • Built Google Play receipt verification and purchase recovery, and verified one real charge and a single grant on Android
  • Connected Addressables to Cloudflare R2 for skins, combat models and audio, with built-in assets as a fallback
