What I built

The whole company blog: post list, categories, tags, search, an admin editor (TipTap), Docker image build and EC2 deployment, RDS PostgreSQL. Completed in eight PRs.

Traps recorded

  • NEXT_PUBLIC_* is baked in at build time, and standalone output does not serve public/ at runtime. The Docker image copies public separately.
  • The client IP that rate limiting sees depends on which position in the proxy header chain you trust. ALB and nginx both append a value, so the position our own proxy wrote is the one to trust.
  • TipTap tables vanish without warning if the extension is missing, and descendant selectors add margins to <p> inside cells. @tiptap/* versions are pinned together.

Summary

A Next.js + PostgreSQL blog deployed in Docker on EC2. TipTap editor, tags and categories, search, rate limiting. Documented traps around build-time env vars, standalone static files and proxy header trust.

  • NEXT_PUBLIC_* is build-time and standalone output does not serve public/ at runtime: copied separately into the image
  • Which position in the proxy header chain you trust decides the client IP that rate limiting sees
  • TipTap tables vanish silently without the extension: @tiptap/* versions pinned together
