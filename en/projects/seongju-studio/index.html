How it works

1. Set up the team

I organize planning, art, client, backend and QA work into teams with leads and assigned staff. Selecting an ID card opens task assignment, messages and the employee record.

Each agent has its own runner, such as Claude Code or Codex, along with a model, skills, MCP tools, file and shell permissions, and time and cost limits. Revision requests and my feedback can be saved as memory for the next task.

2. Turn a brief into a project

New projects start from a playbook for a game, an app, a video or a 3D asset. The game MVP playbook runs through concept, design, technical and art review, task breakdown, parallel production, device QA and final approval.

For an existing project, I import its Git repository, choose the base branch and describe the work to continue from there.

3. Assign and run tasks

I put an assignee and acceptance criteria on each task card. The core manages the queue and the canonical Git repository. A runner executes each assignment in a separate Git worktree and can be selected for the tools or devices it has.

The task detail shows the assignee, run history, changed files and diff. Revisions continue on the same branch. Changes requiring my approval are merged into main after I approve them.

4. Review results and approve

The runner can capture desktop and mobile web screenshots or Unity game views from the task branch. Unity assignments can include compilation, EditMode and PlayMode tests, and a first-scene play check. Runners can also run Blender jobs and export FBX.

The lead reviews the diff and screenshots and passes the work or requests changes. A QA lead can consolidate device findings into fixes and another test pass. I use the inbox to give final approval or return the task with feedback.

5. Turn meeting decisions into tasks

I choose the agenda and participants. After the agents discuss it, a moderator records decisions, action items and open questions. I can create a task for an assigned action item from the meeting record.

Direct instructions, reports and approval outcomes stay in the staff member’s message thread. Meeting notes can be saved to the knowledge base for later work.

6. Track work and usage

The dashboard groups runtime and tokens by employee, model and task. It separates API charges from estimated subscription usage and shows the cost of repeats, including revisions and merge conflicts.

Using it at the AI TOP 100 final

I used Seongju Studio, a tool I built, to delegate log analysis to supporting agents at the AI TOP 100 final. The primary agent used their analysis to choose its next actions. AI TOP 100 case study

Review and learning per agent

For web games, I added a play check that sends inputs and records errors and long stalls alongside screenshots. Reviewers can inspect the diff and the play results for the same task.

I record the reviewed commit so a follow-up review can focus on the new diff. If a required fix remains after the final review, the change goes to the operator instead of merging automatically. Agents can propose skills and MCP tools for their roles, with adoption governed by policy. Adoption and tracked use contribute to experience, and memory cleanup preserves operator notes and a rollback copy.

Summary

I assign agents to design, art, development and QA roles. Each task has its own Git worktree, and changes merge after review and approval. I used the tool at the AI TOP 100 final to assign log analysis to supporting agents.
