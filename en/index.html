05

AI

Writing and verifying code with AI tools is daily work. Below are things I can show as artifacts rather than claims. The code is taken from the repositories as is (comments are in Korean).

  1. 01Built my own agent: seongjuclaw

    Python · Claude API · Ollama · Jul 2026 –

    What
    An agent that uses the terminal, files and the web as hands. Tool loop, a SKILL.md skill system, session save/restore, serverless local RAG (fastembed), local models via Ollama, a closed-network mode that blocks every outbound call, a desktop GUI.
    Why
    To direct tools like Claude Code well, I wanted to know how they run inside: tool-call ordering, context management, the safety conditions for parallel execution.
    Verified
    RAG and the tool loop were run end to end with a real model. The GUI was run in closed-network mode with a local model (gemma4 12b) reading files and answering, captured in September 2026.

  2. 02Moved work to local models to cut the token bill

    Ollama · llama.cpp · vLLM · fastembed · 2026

    Why
    Every extra API call cost money. Research, summarizing and classification do not need top-tier models, so they moved down to local ones.
    How
    My own agent runs Ollama on the same tool loop as Claude, so only the model swaps, and a closed-network mode blocks every outbound call. RAG runs serverless on fastembed and numpy, so no embedding API either.
    At work
    The air-gapped AI product runs entirely on local models (vLLM, Ollama). Moving embeddings to the GPU cut the first response from 20 s to 1.2 s, and the AI security product runs its judgment model locally on llama.cpp.
    Limits
    A local 9B loses formatting on long context, so I split work by task between local and API.

  3. 03Built Unity-specific build automation

    Python · Unity batch mode · Aug 2026

    Why
    Five years of CI kept tripping on the same things: exit code 0 on a failed build, -quit conflicting with test options, license seats never returned.
    How
    I wrote the traps you only learn by getting burned as module documentation first, then let the agent implement. Domain knowledge from me, implementation speed from AI.
    How far
    The verdict logic that trusts the build report and log signals over the exit code is pinned by tests. This Mac does not have that Unity version, so it was never run end to end on a real project, and I say so.

  4. 04QA, build and operate AI products

    AEGIS · Independent Intelligence · AAC chatbot · 2026

    AEGIS
    An AI security gateway (AI DLP). GS certification defect follow-ups (one defect = one PR); for a financial-sector rollout, a pre-delivery checklist measured by hand surfaced role-boundary, audit-ledger and Korean PII detection defects, which I fixed.
    Independent Intelligence
    An air-gapped workplace AI. Pre-launch QA, gateway hook and document tool fixes (0% → 99% over 100 runs), and a rebuild of the dead server on a Jetson with two domains live.
    Rule
    Agents may write code but never deploy. Irreversible actions are pressed by a person.

When I hand work to AI

  • Rules go in documents. CLAUDE.md and HANDOFF.md per repo, SKILL.md for the agent. What not to do comes first.
  • Domain knowledge from me, implementation together. Traps you only learn by getting burned are written down first. Not knowing that a dev auth bypass silently falls back to admin makes you read a permission test backwards.
  • Results get re-checked. Build, run, screenshot, measure. "Done" only after I have seen it.
  • Irreversible actions stay human. Deploy, publish, delete, pay: never the agent.
